Local results are recorded in [local-validation.json](evidence/local-validation.json). AWS and GitHub settings below require observations from the deployed account or repository settings.

| Evidence | Acceptance |
| --- | --- |
| CRUD request output | POST 201, GET 200, PUT 200, DELETE 204, deleted target 404 |
| DynamoDB targets | The corresponding creates and updates appear in the correct environment |
| Crawler result | Enabled API-created target appears; disabled target does not |
| Three integration tests | Passing JUnit report in Beta, Gamma and Prod |
| DynamoDB performance | Real read/write measurements with units and workload described |
| Successful pipeline | One revision passes build, Beta, Gamma, approval and Prod |
| Failed test blocker | Failure stops progression to the next environment |
| Dashboard | Recent target, invocation, error, duration, timing and memory observations |
| Genuine alarm | Real failed invocation or release triggers CloudWatch |
| Canary rollback | Deployment ID, alarm state and live alias before/after recovery |
| Operational rollback | Successful release history, subsequent alarm and previous version restored |
| SNS notification | Confirmed subscription and received notification if email configured |
| GitHub merge protection | validate is a required check on main |
| GitHub Project board | Stories have status, priority, owner and acceptance criteria; links resolve |
| Cleanup | Project stack deletion and post-delete resource verification |
| Personal contribution | Commits, linked issues and an explanation of the implemented modules |

A manually supplied SNS test message proves notification delivery. Its meaning is different from a CloudWatch alarm generated by actual telemetry. Label each screenshot and report entry with the operation it actually demonstrates.
