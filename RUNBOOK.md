# WebHealth Runbook

## Purpose

This runbook provides operational instructions for monitoring, troubleshooting, and maintaining the WebHealth application.

The system monitors website health using AWS Lambda, Amazon CloudWatch, Amazon SNS, and Amazon DynamoDB.

---

# Check Website Health

1. Open AWS Console.

2. Navigate to:


CloudWatch → Dashboards


3. Open:


WebHealth-Dashboard


4. Review the monitoring graphs:

- Availability
- Latency
- HTTP Status Code

5. Check CloudWatch alarms for any triggered alerts.

---

# Monitoring Metrics

## Availability

Availability indicates whether the website successfully responds.

Values:


1 = Website is available

0 = Website is unavailable


If availability becomes `0`, investigate the website connectivity and Lambda execution.

---

## Latency

Latency measures website response time.

Unit:


Milliseconds (ms)


Higher latency indicates that the website is responding more slowly.

If latency exceeds the configured threshold, CloudWatch will trigger an alarm.

---

## Status Code

The system records HTTP response status codes.

Examples:

| Status Code | Meaning |
|---|---|
| 200 | Successful response |
| 404 | Resource not found |
| 500 | Server error |

---

# Alarm Notification Process

When a website problem is detected:


CloudWatch Alarm
|
↓
SNS Notification
|
├── Email Alert
|
└── Alarm Logger Lambda
|
↓
DynamoDB AlarmLogs


The alarm notification is:

1. Generated by CloudWatch.
2. Sent through SNS.
3. Delivered to subscribers.
4. Stored in DynamoDB for historical records.

---

# If a Website Has a Problem

Follow these steps:

## Step 1: Check CloudWatch Alarm

Open:


CloudWatch → Alarms


Check:

- Alarm name
- Current state
- Threshold condition
- Alarm reason

---

## Step 2: Check Lambda Execution

Open:


AWS Lambda


Check:


WebHealthFunction


Review:

- Invocation count
- Errors
- Duration
- Execution status

---

## Step 3: Check CloudWatch Logs

Navigate to:


CloudWatch → Log Groups


Check:


/aws/lambda/WebHealthFunction


Look for:

- Connection errors
- Timeout errors
- Invalid website URLs

---

## Step 4: Test Website Manually

Open the website URL manually or use a browser/network tool.

Check:

- Website accessibility
- Response speed
- Server availability

---

# Checking Alarm History

To check previous alarm events:

1. Open DynamoDB.

2. Navigate to:


Tables → AlarmLogs


3. Review stored records:

- Alarm name
- Alarm state
- Reason
- Timestamp

---

# Common Issues

## Website Unavailable

Possible causes:

- Website server downtime
- Incorrect URL configuration
- Network issue

Actions:

1. Verify the website URL.
2. Check Lambda logs.
3. Test the website manually.

---

## High Latency

Possible causes:

- Slow website response
- Network delay
- Server performance issue

Actions:

1. Review latency metrics.
2. Check recent trends in CloudWatch Dashboard.
3. Investigate the website performance.

---

## No Alarm Notification Received

Check:

1. SNS subscription status.


SNS → Topics → WebHealthAlarmTopic


2. Confirm email subscription.

3. Check CloudWatch alarm state.
